# dsh-audio-release-kit

Part of the local/custom **DeepSeek Harness Audio (Local Build)** distribution, built from the official DeepSeek Harness 0.1.5-rc.1 source. It is **not** an official DeepSeek release.

- **Preset:** read-only agent preset **DGX audio (no tools)** (`presets/dgx-audio`) for audio models that reject tool calling. Desktop discovers it through `dsh.agentPresets` (local host patch 0004). On Web/CLI, copy `presets/dgx-audio` to `$DSH_HOME/.agent-presets/dgx-audio`.
- **Settings → Plugins → Audio servers:** add or remove OpenAI-compatible vLLM / vLLM-Omni servers into the `dsh-dgx-audio` settings section.
  - **Presets:** the form offers the SBPLab DGX Spark models (MiniCPM-o 4.5 on port 18124, MiMo-Audio-7B-Instruct on port 18212). A preset model also gets its recipe request values: MiniCPM `chat_template_kwargs`; MiMo `maxTokens: 200` and a short system prompt. Tests: `test/presets.test.ts`.
  - **Audio models configured:** when a server is configured in Audio models (dsh-audio-model-library), the card tells you to use Audio models → Refresh. The manual form sits behind "Add a server manually". Servers that Audio models already serves are listed read-only. **Test connection** runs only when you click it, as a host reachability probe with no inference. Each model's capability state is shown truthfully (verified / not tested / declared / advertised).
- **Voice conversation** (left sidebar): a live, hands-free voice call with a realtime audio model (MiniCPM-o 4.5 full duplex). Start, then just talk: no record/stop/send. Mute, Stop reply and End; a two-lane timeline (you / model, 1-second decisions) and live captions. **Stop reply** stops playback at once (also when the server has already finished generating), cancels a reply that is still open with `cancel-response`, and sends a truncating playback ack so the model keeps only what was heard; until you have spoken again (your turn has ended), replies the model starts by itself are cancelled and not played ("Waiting for you"). Reply audio starts 0.3 s ahead of the clock and buffers up to 1 s more after gaps; Details shows gaps, the buffer and the server's cancellation time. The microphone opens only after **Start conversation** and closes on **End**. Audio only in this iteration: the call is not yet written into the conversation, and there is no camera. When the call opens, replies play only after you have spoken (the model can start talking into the silence by itself).
- **Language hint:** the system prompts say the user is expected to speak Chinese; no reply language is imposed (`src/client/reply-language.ts`). The hint is in the voice page's duplex instructions (after MiniCPM-o's default "Streaming Omni Conversation."), in the "DGX audio (no tools)" persona, and in the MiMo preset system prompt. Start a new conversation to get it in chat.
- **No first-run dialogs:** the upstream "Internal Testing Notice" and the DeepSeek API key step do not open at startup (both `settings.onboarding` steps are shadowed by entries that complete at once; see `src/client/StartupDialogs.tsx`). To use the official DeepSeek API, set the key in Settings → Models.
- **Composer chip:** when an audio-adapter model is selected in a non-audio preset, a blank conversation switches to the audio preset in place; a started one gets a new audio conversation with the same workspace and model.
- No network access of its own beyond the host's own routes: `/api/dsh-dgx-audio/v1/*` (including the voice page's `live/*` and `events`), plus a read of `GET /api/dsh-audio-model-library/v1/library` when the Audio servers card is opened (it contacts no model server). No credentials: only an environment-variable **name** may be stored for API keys.
